## Contributing

This lesson uses the [Carpentries template][template-doc] and incorporates elements from the [Carpentries teaching philosophy][instructors]. The authors of this lesson are Carpentries trained instructors and maintainers. However, this lesson has been developed with a narrower scope than the official Carpentries lessons. The goal of the creators is to use it only in the context of workshops taught at Oregon State University (OSU). For example, as part of the [OSU Libraries Workshop Series][osulp-workshops].

This lesson is openly available, and published under an [open license](LICENSE.md). We welcome contributions to fix existing material, and reviews of proposed changes. However, keep in mind that we may not be able to accept appropriate contributions if these do not fit the context under which this lesson will be taught. 

### Contributor Agreement

By contributing, you agree that we may redistribute your work under [our license](LICENSE.md).

### How to Contribute

You can contribute to this lesson using any of the following methods:

1. If you do not have a [GitHub][github] account, you can [send us comments by email][contact]. 

2. If you have a [GitHub][github] account, or are willing to [create one][github-join], but do not know how to use Git, you can report problems or suggest improvements by visiting the GitHub repository for this project and creating an issue. 

3. If you are comfortable with Git, and would like to add or change material, you can submit a pull request (PR). 
   Instructions for doing this are [included below](#using-github). 

All contributions should be made in accordance with the Carpentries' [Generative AI Contributions Policy][ai-policy].

### Where to Contribute

1. If you wish to change this lesson, add issues and pull requests here.
2. If you wish to change the template used for this lesson, please refer to the Carpentries' [Workbench documentation][template-doc].

### Using GitHub

If you choose to contribute via GitHub, you may want to look at [How to Contribute to an Open Source Project on GitHub][how-contribute].
In brief, we use [GitHub flow][github-flow] to manage changes:

1. Create a new branch in your desktop copy of this repository for each significant change.
2. Commit the change in that branch.
3. Push that branch to your fork of this repository on GitHub.
4. Submit a pull request from that branch to the upstream repository.
5. If you receive feedback, make changes on your desktop and push to your branch on GitHub: the pull request will update automatically.

NB: The source files of the published copy of the lesson is usually in the `main` branch.
